# Roadmap / 路线图

The 0.2.0 candidate establishes a public pinned dependency and a managed installation interface. Its acceptance status is recorded in [validation](docs/validation.md); implementation and a successful check must not be presented as a human usability result.

0.2.0 候选版引入公开固定依赖和统一安装管理接口。各项验收状态见验证说明；实现或工具检查通过，不代表真人使用效果已经得到证明。

Priorities below have no promised dates:

1. **Complete candidate acceptance.** Exercise package failures, the public provider, reversible installation, and independent fictional development scenarios. Keep unperformed checks and failures visible.
   **完成候选验收。** 验证包的失败分支、公开依赖、可逆安装和独立虚构开发任务，保留未执行项与失败。
2. **Observe clean Codex desktop App onboarding.** Verify installation, discovery in a fresh conversation, actual invocation, and recovery in the stated App environment.
   **实测干净 Codex App 接入。** 分别验证安装、新会话发现、实际调用和恢复。
3. **Maintain upstream alignment.** Review official Superpowers updates as candidates, inspect method changes, rerun relevant compatibility checks, then release a new supported combination. Never silently update an active task's provider.
   **持续对齐上游。** 将官方更新作为候选审查，检查方法变化并验证后发布组合，不静默改变任务依赖。
4. **Measure workflow usefulness.** Declare reproducible synthetic scenarios across new work, maintenance, continuation, missing tools, and failed research. A later comparison with Superpowers alone needs comparable tasks and honest failure reporting.
   **衡量流程价值。** 用可复现合成任务覆盖不同入口及失败条件；如进行 Superpowers 对照，先明确同等条件并如实报告失败。
5. **Study beginner usability.** Invite consenting first-time users to purpose-made fictional tasks and observe confusion, recovery, and completion. Do not collect or publish their real projects or task logs by default.
   **研究新手可用性。** 在明确同意下，邀请首次使用者完成专门虚构任务；不默认收集或公开真实项目及日志。
6. **Extend client support only after evidence.** Validate installation ownership, discovery, available tools, and task behavior for each client and platform before advertising support.
   **有证据后扩展客户端。** 各客户端与平台分别完成安装、发现、工具和任务行为验收后，再声明支持。
