# Task record

Template instructions: create only when useful; replace explanatory content with facts or remove unused sections. Preserve the project's existing design, plan and ledger as the source of truth. This template is not an actual completed task.

## Goal and requested deliverable

Record task identity, requested output, scope and explicit restrictions.

## Acceptance

List observable conditions, their verification methods and current status.

## Decisions

Separate user decisions, agent defaults and unresolved questions. Link any required approval to its actual subject and scope.

For a new project, link the existing reuse/differentiation decision and its evidence, including complete alternatives, useful parts, the selected route, the user's decision and remaining uncertainty. Use the optional [decision card](reuse-decision.md) only if no existing artifact already captures it.

## Workspace and baseline

Record the resolved path/mode, relevant existing edits, baseline failures and authorized side effects. Never store credentials.

## Provider and current phase

Record the actual profile identity, content/behavior evidence status, current controller and bounded assignments.

## Artifact index

Link existing design, plan, ledger, implementation reports and test evidence. Do not duplicate their contents here.

## Verification and failures

Append the checked artifact state, command/inspection, inputs/environment, actual result and limitations. Retain earlier failed evidence and distinguish baseline failures.

## Next step

State the first unmet requirement, necessary input and safe continuation point.

## Owned resources

If any were started, record task-owned processes/sessions, owner, lifecycle state and confirmed shutdown. Remove this section when unused.
